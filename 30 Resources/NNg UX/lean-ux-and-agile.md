# Lean UX and Agile [2015–17]

Source: NN/g "Lean UX and Agile" (2016). Hub: [[30 Resources/NNg UX/README|NN/g hub]]. Delivery-framework context: [[30 Resources/SAFe/README|SAFe hub]].

- **Tension:** agile values speed of release and "simplest solution", not the most usable one; UX is rarely part of the original manifesto. Ways to integrate UX: designer embedded in every stage, part-time designer across teams, designing ahead of development (dual track) or design and build in the same sprint.
- **Practices that work:** stable teams (reshuffling kills learning), design at the right level of detail for the time, shared UI pattern libraries, release planning and story mapping that include UX, UX estimates factored into planning so work is visible, definition of done includes usability testing with no serious issues, and everyone owns the experience.
- **User stories:** "As a <role>, I want <goal>, so that <reason>" keeps focus on need, not implementation; keep close collaboration with the product owner.
- **Lean startup vs Lean UX:** lean startup (Ries) asks should we build it (MVP); Lean UX (Gothelf) asks is the design usable (wireframes, prototypes). Replace assumptions with hypotheses ("we will know this is true when we see…") and a culture of verifying; RITE (rapid iterative testing and evaluation) and testing at any fidelity.
- **Measures:** satisfaction scales, recommendation (NPS-style), SUS-type 10-item questionnaires.
