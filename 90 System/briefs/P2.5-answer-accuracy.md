# Answer accuracy: a layered plan, measured at every step

## Goal (one sentence)
Make Ask Brain answers correct, honest and checkable by fixing each cause of error at the cheapest layer, and score every change on a fixed test set.

The answer: "There is no [section] according to the evidence", yet the cited row says "Sat 10 Oct, Normal meeting, 14:00–17:30" | The note is minimised (data-policy §3a: no unit name), so David's word is not in the text. ## Decision (David, 5 Oct, [[90 System/for-david|Q47]]): run all seven layers, in this order
1. **Test set first.** 30 questions with expected answers and evidence, labelled by type: lookup, date (evaluated against a fixed test date), negation, should-decline, synthesis. Keep a held-out subset that no tuning touches. Report per-type scores, not one average. Every later layer is scored before and after.
2. **Date awareness** (already priority 2 in handoff): current date in every request, relative dates resolved before retrieval, the date stated in the answer, honest "nothing for that date".
3. **Structured fast path for schedules. Gated on H1** (data-policy §3a.6: no family-logistics features before the H1 gate). Until the gate is met this layer is skipped and schedule questions go through layers 4–5. Wave-1 logistics notes (menus, bins, activities) are tables. Parse them into structured records (date → items) at index time. Date-shaped questions about them are answered by a deterministic lookup; the LLM only phrases the result. The answer cites the exact row. Each parser is small and tested; a note that doesn't parse falls back to the normal path. Children's rule §3a still applies: no names, places or new fields.
4. **Retrieval:** split tables into row chunks that keep their header, weight note titles and headings higher, rewrite queries (dates, synonyms, FR/EN). **No vector database (D5)**; lexical and structural only.
5. **Prompt:** quote the evidence line first, then answer from it; fact first, no yes/no lead-in; an explicit rule to decline when the evidence doesn't answer the question.
6. **Model swap:** T9/M6 on the Air (Qwen3.5-4B, Gemma 4 E4B, Ministral 3 8B) scored on this test set, latency alongside. This is an additional evaluation next to [[90 System/briefs/T9-M6-model-comparison|T9]]'s frozen ten-case protocol, not an amendment to it. Then 14–30B candidates on the Mac mini when it arrives (Q30).
7. **Verification (T4.1):** a second pass checks that the answer follows from the quoted evidence; only then may an answer be labelled `supported` ([[90 System/for-david|Q21]]).

1. **F0 · Files in scope and regression cases.** List the files this slice may change (expected: `dbrain/answer.py`, a new `dbrain/aliases.py`, `dbrain/serve.py` for status mapping only, tests, a regression-case file); Codex reviews the list. Baseline them on the current code. Commit.
2. **F1 · Prompt rule (layer 5).** Quote the matching evidence line first; if a cited row carries the asked date, answer from it and, when the asked term is absent from the note, say so ("the note doesn't use that word, but on Sat 10 Oct it lists …"); decline only when no evidence holds the asked date and entity. Score F0's cases and the dev cases before/after. Commit.
3. **F2 · Deterministic contradiction check (part of layer 7).** After the model answers: if the answer is a negative ("no", "nothing", "pas de", "rien", "geen", "niets", …) and a chunk the answer itself cites (never another retrieved note, so case (d)'s correct "no" stands) has a line that holds the resolved asked date and lists an event on it, with no negation of its own on that line (so a note line "no meeting on …" never triggers it and F0 case (c)'s correct "no" stands), the verdict becomes a defect `incomplete` with a new reason code (e.g. `negation_vs_dated_evidence`) and the phone reply shows the dated row instead of the "no". Being a defect, it is a P2.7 failure signal, so it is captured. Tests for EN/FR/NL negatives and the three F0 cases. Commit.
4. **F3 · Alias list for query rewrite (layer 4, minimal).** A small alias table (David's word → note wording), generic terms only, no names or places (§3a), loaded read-only; query terms expanded before retrieval. Seed: `baladin(s)` → `scouts`, `section`. Tests. Commit. **Stop and report:** before/after per case, in plain language first.
