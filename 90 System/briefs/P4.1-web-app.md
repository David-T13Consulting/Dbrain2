# Ask Brain by voice first; web app last

## Goal (one sentence)
Replace the Shortcut pop-up with a private, app-like chat screen on David's iPhone that shows answers, quoted sources and status, served by the Air over Tailscale. Then add push-to-talk with local transcription.

## Voice first (David, 5 Oct, Q50, supersedes the ordering below)
David doesn't want a web app now. He wants to **ask out loud and hear the answer**. So:
- **Voice step A (now, after the MVP merge):** `/ask` returns a `speech` field: one or two short spoken sentences, fact first, stating the date it answers for, no paths or line numbers. The Siri Shortcut "Ask Brain" dictates the question, **speaks `speech` aloud**, and shows `display` (sources, status) on screen. Errors are spoken too ("Your Mac is asleep", "Not authorised"). David rebuilds the Shortcut by hand from Cowork's recipe, with a Speak Text step added: Q56 retired the builder script (`mvp/make-shortcut.sh`), and no agent writes a file that carries the token.
- **Voice step B (after the T9 comparison):** local transcription without a web app. The Shortcut records audio (Record Audio) and posts it to `/ask/voice`; the Air transcribes with whisper.cpp, deletes the audio (D58), answers and returns `speech` + `display`. That replaces Apple dictation with on-device transcription.
- **The web app (v1 scope below) moves to the very end of the queue.**

## Earlier decisions (David, 5 Oct; Q48–Q49)
- **Web app (PWA) served by the Air**, saved to the iPhone home screen; slotted **right after the date fix and the MVP merge**. The Shortcut stays only as a Siri voice entry ("Hey Siri, Ask Brain"). *Timing assumed by Cowork from David's answer; he asked about voice rather than picking a slot.*
- **Voice:** v1 uses iOS keyboard dictation plus a 🔊 read-aloud button (on-device speech synthesis). **v1.1 adds push-to-talk**: audio goes to the Air, is transcribed locally (whisper.cpp), and is deleted after transcription (D58). FR, EN and mixed.

## v1 scope
1. **Chat screen:** question box, answer with the date it answers for, status badge in plain words ("Not verified", "From an unreviewed Inbox note"), quoted source lines, tap a source to open the cited lines (read-only view).
2. **History** of this device's questions, stored on the Air in the git-ignored runtime folder, never in the vault; can be cleared.
3. **Read aloud:** 🔊 on each answer (browser speech synthesis, on the phone).
4. **Offline and errors:** clear messages ("Air asleep or offline", "Not authorised"); a request timeout with a message, never a hang.
5. **Auth:** HTTPS via `tailscale serve` (the Air's ts.net name and certificate); only tailnet devices. Login once per device with the existing token, exchanged for an httpOnly, secure session cookie; or a passkey if simple. The token is never stored in page script or localStorage.
6. **Install:** web manifest + icon, so "Add to Home Screen" gives an app-like full-screen view. Mobile-first layout, dark mode.
7. **Same `/ask` backend**: no new model path, no cloud calls; read-only; all D69, §3a and Q21 rules unchanged.
