# Session taxonomy v2: separate format, intensity and context (option B)

> Written by Cowork, 2 Oct 2026 as provisional **T3.5** / **D-cowork-5**; renumbered to **T3.4** and **D67** by the lead in session 14 (T3.4 was the next free ID, D67 the next free decision number). David chose option B on 2 Oct: "I agree with option B". This brief is a **proposal to review**. Nothing in the rubric, skills or golden files changes until David approves the spec below.

## Goal (one sentence)
Replace the single mixed `intent` axis with orthogonal, rule-checkable axes, each aligned to the vocabulary used by Runna, Strava, Campus and Garmin, so labels stop needing patch decisions like D28/D36/D37/D40/D66.

## Why (evidence, 2 Oct)
- `intent` currently mixes **format** (intervals, hills, long), **intensity** (easy, tempo) and **context** (race, post-race recovery). Five decisions so far patch that mix: D28 and D40 (long + tempo), D37 (hills vs intervals), D66 (race vs tempo), and the batch 04 relabels of #13 and #19.
- Our `tempo` (marathon pace or faster) is Runna's *steady*. Runna, Campus and Garmin all put tempo/threshold near lactate threshold.
- Missing types that occur in David's data: threshold reps (batch 04 #1), progression (23 Aug 2026), time trial (27 Jan 2026), fartlek, strides.
- Industry references: Runna coaching terms; Strava activity tags (Race ≠ Competition; tags stack); Campus (endurance fondamentale, seuil 60/30, VMA, côtes, sortie longue; intensities relative to the athlete); Garmin Training Effect (Recovery, Base, Tempo, Lactate threshold, VO2 max, Anaerobic, Sprint). Links are in the 2 Oct Cowork chat; copy them into `30 Resources/Running/` sources when the spec is approved.

## Purpose test (David, 2 Oct)
The taxonomy serves two consumers only: (1) the weekly assessment flags (F3 quality work, F4 long run, race / post-race weeks; F2 reads HR time directly), and (2) the golden dataset as checkable receipts for the demo. **An axis or value earns its place only if a downstream rule uses it and a deterministic rule can reproduce David's label.** Industry alignment is a bonus.

## Schema v2 (approved in principle by David, 2 Oct; final wording at rubric v2.0)
| Axis | Values | Set by |
|---|---|---|
| **Terrain** (unchanged) | road · trail · mountain. A running track counts as road | rule, T1–T4 as in v1.4 |
| **Format** | continuous · progression · reps · hill reps | rule, from laps/streams. reps = ≥3 work/rest alternations; hill reps = work parts ≥5% grade (D37); progression = ≥3 segments with pace/HR rising monotonically |
| **Dominant intensity** (time-weighted on the work parts) | recovery/base (≤Z2) · steady (Z3) · threshold (Z4) · VO2max+ (Z5) | rule, from the **Friel HR zones** in `athlete-baseline` (dated rows). Fallback for short reps on flat road, where HR lags: pace against the race-pace rows |
| **Context** (flags that can stack) | race · competition (event at training effort) · time trial · post-race window · long (duration/km-effort, D40) | rule + names/description. D66: a race is never also a tempo block |
| **Flags** | `vertical` (unchanged) · minutes in steady / threshold / VO2max+ (replaces `tempo_block`) | rule |

**Derived for the weekly flags:** quality work (F3) = format reps or hill reps, **or** dominant intensity threshold or above. Long (F4) and race weeks come from the context flags.
**Mapping layer (option C):** each label maps to a Strava tag (Race, Long Run, Workout, Recovery, Competition) and a Garmin primary benefit, for the demo.

## Decided by David, 2 Oct ("yes to all")
1. **No purpose axis.** No consumer uses it and no rule can check it.
2. **No track terrain**: a track is road.
3. **Threshold boundary = HR zones** (Z4 by LTHR), with pace as the short-rep fallback. This makes the LTHR re-test (OQ-6) more urgent: under v2 the whole intensity axis depends on it.
4. **Relabel batches 01–04 by rule-derivation**: rules derive the axes, David resolves only the disagreements, and every disagreement is logged (demo material).
5. **Drop fartlek and strides.** They change no weekly flag (purpose test).
